Defining "Factory Games" with Design Patterns

Factory games are defined not by theme, but by four recurring design patterns.

What Is a Factory Game

The genre I attempt to define in this journal is the factory game. In player communities, the term "factory game" is commonly used to describe games like Factorio.

In a real-world context, a factory is a production system that uses automation, spatial organization and division of labor to turn repetitive work into a scalable and systematic process. Factory games express this same core idea in interactive form. Rather than simply simulating the act of making items, these games place the player in the role of a designer and manager. The player builds automated production processes and organizes how resources move through space, instead of manually producing each item.

Based on this understanding, factory games can be defined not by theme or presentation, but by a set of recurring design patterns. I define factory games using four core patterns: Automated Production, Quantifiable Production, Scalable Replication and Modularity, and Spatialized Logistics.

Four Core Design Patterns

Pattern 1: Automated Production

In games with this pattern, players design, build and adjust production structures so that resource transformation, transportation, processing and consumption can happen automatically, without the player repeatedly performing production actions.

This pattern is central to factory games because it shifts the responsibility for production from the player's manual actions to the system itself. If production still relies on constant player input, increasing output can only be achieved by spending more time and effort, which quickly turns the experience into repetitive labor. In contrast, automated production makes expansion a question of planning and design, rather than a test of patience or mechanical effort.

Pattern 2: Quantifiable Production

This pattern describes production systems with clear, stable and calculable relationships between inputs, outputs and processing rates. Resource recipes, machine speeds and overall throughput follow consistent numerical rules, allowing players to understand how the system works rather than relying on intuition or trial and error.

The key to this pattern is that production outcomes are deterministic and predictable. Given a fixed input and structure, the output does not change randomly. Players can calculate in advance whether a production setup will meet demand, waste resources or create bottlenecks. Statistics panels and rate displays are not the pattern itself, but interfaces that expose the system's internal logic to the player, supporting deliberate and informed planning.

This kind of quantifiable logic separates factory games from management games driven by vague probabilities or hidden rules. When input–output relationships are unclear, player decisions focus on short-term adjustments and keeping things balanced. Quantifiable production instead shifts the challenge toward designing a logically consistent production structure under constraints of space, scale and resources.

Pattern 3: Scalable Replication and Modularity

In factory games, production systems must support scalable replication. Scalable Replication and Modularity means that production structures can be broken into independent, clearly defined units that can be repeatedly deployed and combined without significantly increasing cognitive or operational complexity.

This pattern is essential because growth itself is a core part of the factory game experience. If every expansion requires redesigning systems from scratch or making detailed, non-reusable manual adjustments, complexity quickly overwhelms the player. Modularity compresses complex systems into reusable units, so expansion does not require solving the same structural problems again. Players can reuse proven solutions and focus on the new challenges that come with increased scale.

Pattern 4: Spatialized Logistics

Spatialized Logistics means that resource transportation, distribution and buffering must happen through structures with explicit spatial constraints. Resources do not move instantly or abstractly through the system. Instead, they travel along visible paths and are affected by distance, path capacity, intersections and layout decisions. Logistics therefore becomes a system that must be designed, not just a background process.

More importantly, spatialized logistics makes system problems visible. When supply is insufficient, resources pile up upstream. When layouts are inefficient, production lines sit idle. When transport capacity is too low, resources visibly stall along routes. These are not abstract warnings but ongoing, observable states. Because problems appear directly in resource movement, players can diagnose where the structure fails and redesign layouts or flows accordingly.

Shapez has no narrative, characters or realistic theme, yet preserves the core structure of factory games in a highly abstract form; Dyson Sphere Program and Factorio differ greatly in presentation and scale, yet both fully satisfy the same four patterns.

Counterexample: Anno 1800

Anno 1800 is often described as an automation or factory game and is frequently included in discussions of the genre. While this classification has some surface-level justification, it does not fully meet the definition established above. It is better understood as a city-building management simulation that uses production chains as tools.

  • Automated Production: Anno 1800 does include continuously operating buildings, but production is tightly coupled to population needs, policies and external supply conditions. Production is never fully delegated to the system; players must constantly intervene to maintain stability.
  • Quantifiable Production: although recipes and production times exist, efficiency is affected by many contextual variables such as happiness, trade conditions and supply fluctuations. Production speed is expressed as time per item rather than stable throughput, making rate-based planning difficult and reducing predictability.
  • Spatialized Logistics: resources are largely abstracted into route-level exchanges. Island inventories are shared rather than stored in observable logistics nodes, and resource flow appears mainly as stock changes rather than continuous movement.

Overall, Anno 1800 focuses on managing a complex economic and population ecosystem. Production chains support city management goals rather than serving as objects of engineering design. So despite surface similarities, Anno 1800 is more accurately classified as a city-building management game, not a factory game.
