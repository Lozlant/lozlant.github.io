概览

愿景：玩家在混乱战斗中享受朋友之间互相使坏的快乐：偷偷背刺得逞时的得意，被背刺时的哭笑不得，以及一局结束后的互相「控诉」。

每位玩家都是一名掌握独有元素的亡灵法师。大家有着共同的目标：把闯进黑魔法景区的教会赶出去。但和谐友爱是不存在的——敌人的灵魂固然是施法的必需品，队友的灵魂却更加强大。

在战斗的关键时刻，背刺你的队友，甚至炸飞他的项上人头吧：更强的攻击、更多的灵魂，都将属于你。又或者，做出一点牺牲，把你的灵魂和力量暂时分享给队友。别担心，伟大的亡灵法师只要让自己的头找回身体，就能复活。

核心体验

  • 混乱中的算计：表面是一团混战，但每次出手都是有得有失的决定。
  • 队友是资源，也是代价：攻击队友能得到增益、灵魂和元素；被攻击的队友可以反击，失去队友也会削弱队伍。
  • 死后的争夺：阵亡后的头颅阶段，仍然有合作与竞争的选择。
  • 派对的愉快感：比起通关技巧和来自朋友的压力，更强调派对般的愉快。
  • 降低通关压力：让不同水平的玩家都能为队伍做贡献。

玩法

Project Lich 是一款 3D 俯视角的 3 人合作魔法战斗游戏。

  • 推进：玩家在名为「黑魔法景区」的场景里前进，击退所有敌人。
  • 灵魂：施法需要消耗灵魂，击败敌人就能获得更多灵魂。
  • 攻击队友：攻击或击杀队友会触发元素反应，获得更强大的攻击能力。
  • 死亡：死亡的玩家会掉落持有的灵魂，变成头颅；变成头颅后仍然可以抢夺灵魂，回到身体就能复活。

核心循环

  1. 战斗
  2. 获得灵魂
  3. 施法
  4. 击败敌人
  5. 回到战斗

死亡循环

  1. 战斗中死亡
  2. 头颅飞出
  3. 找回身体，沿途抢灵魂
  4. 复活
  5. 回到战斗

系统一览

  • 灵魂资源系统灵魂是施法资源：怎么获得、持有、拾取与争夺。基础规则已确定，数值暂定，正在用 Machinations 和 Python 模拟验证
  • 合作战斗与友军伤害核心玩法：攻击队友是有得有失的策略。核心规则已确定，友军伤害数值暂定
  • 攻击队友的奖励对队友造成伤害时，双方各获得一次元素反应攻击；击杀队友引发元素反应爆炸。规则已确定，爆炸连锁等效果待试玩
  • 死亡与复活死亡不是出局：变成头颅，仍可争夺灵魂，复活后回到战斗。规则基本确定，已有 Unity 简易实现
  • 元素每位玩家有一种独有元素。规则框架已确定，元素反应待探索
  • 战斗波次一次战斗由 2 到 3 波敌人组成：刷出、定时与提前清空、战斗结束。基础规则已确定，间隔暂定
  • 敌人 AIPoC 只有一种发射法球的敌人。敌人类型已定，行为待设计

每个系统的设计文档都按「确定、待探索、未定、暂缓」分类，标明哪些可以直接实现、哪些要靠原型验证。

数值与验证

  1. 资源总表各项资源的上限、来源、消耗，作为数值的唯一来源
  2. Python 蒙特卡罗模拟每组设置跑 400 到 2000 局，验证灵魂能否循环
  3. Unity 数据监听记录实测数据，和模拟值逐项对照

第一版模拟的几个结论：

  • 小怪掉 3 个灵魂球时 94.6% 的战斗卡死，掉 4 个是临界点，掉 5 个开始净增。
  • 只靠误伤，每波死亡次数远低于目标；需要玩家主动攻击残血队友，才能让死亡「以队友击杀为主」。
  • 拾取优先权（负反馈）只让灵魂差距缩小 2.6%，作用很小，等实测后再决定是否加强。

风险与应对

  • 玩家对背刺的情绪反应：玩家可能不敢攻击队友，也可能陷入内战、反复被击杀而不满。应对：正在设计，目前用「攻击队友的奖励」鼓励玩家下手。
  • 战斗系统能否体现核心玩法：攻击队友是否有意义，元素与灵魂能否形成真实取舍，敌人与关卡能否制造合适的压力。应对：测试中，用 Python 模拟和 Unity 实测对照验证。
  • 美术范围：两种关卡主题需要的美术资源较多。应对：先做黑魔法景区的部分，再视情况决定是否制作教廷。
